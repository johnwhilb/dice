# 游戏界面美术 Agent 项目指令

## 目标与适用范围

本文件是当前项目的 Codex 工作指令，适用于本目录及其子目录。
根据用户给出的界面名称、尺寸比例、构图、文字和交互状态，制作同一款游戏中风格一致的完整界面美术。
使用中文沟通。游戏名称以用户本次要求为准，不根据工作区文件夹名称猜测。

## 生成前必须执行

1. 美术风格：将维多利亚哥特美学与洛夫克拉夫特式克苏鲁恐怖完美融合
2. 列出并实际打开查看 `画风锚点\` 下的所有参考图片。使用图像查看工具读取像素，不能只看文件名或文字描述。
3. 实际打开查看 `可用界面\` 内的已有界面，识别项目的线条、色板、阴影、材质、字体、按钮和装饰规则。明确区分用户确认的参考图与尚未确认的输出；未经确认的新图不能自动替代原有风格标准。
4. 将用户本次界面要求与`提示词.txt`合并成最终提示词。界面说明决定画什么，布局决定放在哪里，参考图决定怎样绘制。保留文字原文、组件数量、空间层级和布局要求。
5. 画风锚点直接决定角色和敌人的画风、剪影处理与笔触。不要自动复制具体身份、装备、纹章、白底陈列或排列构图；用户指定同一角色时保留身份特征。不能将“不复制具体内容”解释为忽略锚点的造型、比例和轮廓语言。已有界面只辅助布局、UI 和配色，不能覆盖角色与敌人的锚点标准。
6. 按工具要求把参考图传入生成或编辑调用。需要本地参考图时，先查看，再使用工具支持的引用路径；引用数量受限时，先查看全部，再选择最能代表共同画风的参考图。不得声称工具接收了未传入的图片。
7. 使用可用的内置图像生成工具，并遵循相应图像技能。缺失关键文件、图片无法读取或生成工具不可用时，准确说明限制，不声称已完成参考检查。

## 美术一致性

- 保持近景、远景和操作区域的层次；文字区安静，主要操作容易辨识。
- 所有表面保持哑光，无反光；地面干燥粗糙，禁止湿石板、水膜、积水、镜面反射、倒影、连续亮斑及闪亮高光。材质通过轮廓与明暗色块区分。
- 场景和建筑降低细节密度，减少雕花、密集砖缝和碎石杂物。角色和敌人只减少多余链条、挂饰、铆钉、刻纹等次要装饰；剪影处理、比例风格、主要衣褶、服装分区、发丝分组、轮廓轻重与排线笔触必须按锚点，不能通过统一删线、简化剪影或机械降低细节比例改变画风。UI 信息保持完整清晰。
- 对角色、敌人及其头像，锚点原图的造型与笔触优先于历史生成界面。实际生成调用必须引用代表性锚点，不能只把旧界面当编辑对象并口头描述锚点。减少装饰与保持锚点特征冲突时，优先保持锚点特征；无反光要求继续执行。
- 参考图或历史成图中的反光与过密细节不作为继承目标；将最新的无反光、低细节要求明确写入每次实际生成或编辑的提示词。
- 避免偏向照片写实、三维渲染、塑料高光、霓虹泛光或厚重油画。用户明确要求改变画风时，以本次要求为准。
- 比例、尺寸、必需文字、状态和位置按用户要求执行；未指定的细节采用与已有界面一致的合理默认值。

## 每次生成后必须执行

建筑前景同样必须遵循锚点的剪影处理和笔触。用有轻重、收尖与局部断线的墨线、少量顺结构排线及成组哑光暗面加强手绘感；减少砖缝、裂纹、雕花和写实石材纹理。前景轮廓清楚，远景低对比简化，不能把前景画成三维渲染或靠噪点划痕模拟手绘。当前开始界面的重点是右侧与右下方的深色建筑前景。实际提示词与出图检查均须包含这项要求。

1. 实际打开生成结果，检查文字准确性、菜单数量、布局、画布比例以及远近景关系；不能只依赖生成成功提示。
2. 对照 `画风锚点\` 和 `可用界面\` 中本次生成前的参考图，判断是否能看出属于同一个游戏。重点检查线条、色彩、明暗分组、材质、边缘、装饰和 UI 家族特征。
   同时检查表面是否有反光，场景是否过密，以及角色与敌人的剪影、比例、服装分区、轮廓轻重、排线方向和收笔是否与锚点一致。只检查配色或装饰数量不算通过；简化导致画风偏离同样须修正。
3. 若不一致，指出具体偏差，针对偏差修改提示词或编辑图片，再次查看并对比。保留用户要求的构图与文字，不能靠改变布局掩盖画风偏差。
4. 有明显偏差的图片作为草稿保存；如因工具限制无法继续修正，如实标注待修正项，不标为通过检查的最终成图。

## 保存与交付

## UI 拆分与 PSD 复原工作流（必须执行）

用户请求拆分界面、交付 PSD 或复原效果图时，必须先完整读取项目根目录 `UI拆分与PSD工作流程.md`，按其中阶段顺序执行。
先得到边缘干净的透明 UI 总层，验收后才拆独立组件；不能直接从整张效果图裁矩形充当干净组件。
背景与人物从对应素材文件夹读取。普通文字必须使用 Photoshop 可识别的系统字体，保存为真正可编辑的文字图层；仅强风格艺术字允许保留为独立图像。
不得以整张原图、背景与人物混合校正层、截图碎片覆盖或差异残留层伪造复原一致。没有可编辑文字或依赖混合校正的 PSD 只能标记为草稿，不能作为完成交付。
本次仅更新规范不会自动触发重新出图；之后实际拆分任务必须遵守新流程。

- 最终成图保存到 `生成界面\`，命名为 `<游戏名>-<界面名>-v01.png`；已有同名文件时递增版本，保留已有参考图片，不保留提示词。
- 内置工具输出位于其他目录时，将选定成图复制回本项目，保留工具原始输出。
- 交付时展示成图，提供最终文件的绝对路径链接，简述参考一致性检查结果；存在文字、比例或风格问题时明确说明。
- 本文件变更任务本身无需触发图像生成；只有用户要求制作或修改界面时才执行上述生成流程。
