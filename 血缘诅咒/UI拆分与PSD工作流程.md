# UI 拆分与 PSD 复原工作流程

## 目标

先分离背景、人物与 UI，取得干净的 UI 总层，再拆分独立 UI 组件，最后使用项目已有背景与人物素材，结合真实文字图层复原效果图，交付可编辑 PSD。
用户提供的 `拆分ui/角色选择/UI.png` 是 UI 总层组织形式的示例，不代表其边缘、旧头像数量和内容自动成为新任务标准。具体内容与数量以本次效果图为准。

## 一、确定效果图与素材

1. 锁定本次效果图，记录原始尺寸和版本；保留原文件，不覆盖。
2. 扫描 `拆分ui/<界面名>/`、`角色/` 和用户指定的背景、人物目录，实际查看素材，建立来源清单。
3. 背景优先取对应界面目录的 `背景.png`；人物优先取用户确认的角色素材，不误用旧人物图。
4. 对照效果图检查是否为同一背景、人物、姿势和版本。先调整真实素材的位置、比例、遮罩与必要内容。素材不匹配时明确记录并修正对应素材，不用混合场景校正层覆盖差异。
5. 保留原画布坐标。文字区、技能区、按钮和人物遮挡关系均以效果图为准。

## 二、先制作透明 UI 总层

1. 第一阶段输出与效果图同尺寸的 RGBA `UI总层.png`，保留全部 UI、头像、技能图标及文字的原位置。移除场景与大人物立绘；UI 内的角色头像属于 UI，不误删。
2. UI 自身的黑色、酒红色底板与技能插图底色必须保留，不能把深色误当背景删除；背景透明必须是真实 alpha，不能用黑底或棋盘图冒充。
3. 不从截图矩形裁切出包含场景的组件作为最终素材。不通过重新设计图标或加粗边框替代提取。
4. 在白底、深灰底、棋盘底分别查看总层，并在 100% 与放大视图检查：无白边、黑边、彩色杂边、光晕、远景残留、人物碎片、漏抠和断线。
5. 保留必要抗锯齿、细线、尖角和图标内部不透明区域，不能靠粗暴透明度阈值损伤边缘。
6. 先修正总层问题，再继续详细拆分。记录总层验收结果，不以工具成功返回代替目视检查。

### 边缘处理与原位更新要求

- 禁止把矩形裁切直接当作已去背景的装饰或分隔线。细线、圆形徽章、羽毛、尖角底板、空框分别建立符合实际轮廓的遮罩，不能共用椭圆或统一阈值。
- 抗锯齿边缘必须同时检查 alpha 和 RGB 中残留的原背景底色，不能仅降低透明度。灰底污染须去底色，避免缩放后出现浅边或彩边。
- 先在原始分辨率处理轮廓与遮挡，再一次性缩放到交付尺寸；缩放后再次进行白底、深灰底与棋盘底检查。发现污染时返回原尺寸组件修正，禁止在最终 PSD 上盖色块遮住。
- 验收顺序为单组件、UI 总层、最终 PSD。分别关闭背景与人物，确认独立 UI 不残留场景、人物碎片、重复图标或文字影子。
- 用户要求在当前版本修改时，原位更新当前 PSD、组件、总层、预览、布局数据和验收说明，不创建新版本、新文件或备份副本。其他任务仍按原版本保留规则执行。

## 三、从通过验收的 UI 总层拆组件

1. 独立拆出按钮底板、按钮图标、面板、普通/选中边框、选择标记、纹章、装饰、分隔线、状态图标、各职业技能图标与头像。
2. 头像、框、选中标记分别保存；框内透明。技能插图及其框可按交互需求分开，明确是否包含边框。
3. 按钮、面板底板应去除文字和独立符号，补齐遮挡处。修复不能留下字影、贴片块、接缝或重复纹理。
4. 同类型状态对齐尺寸和锚点。用清单记录文件、尺寸、原位坐标、透明区域、状态、处理方式及素材来源。
5. 每个职业的技能图标分别提供，不以当前选中角色的图标替代其他角色。
6. 将组件复合回原位，与已验收的 UI 总层对照，定位缺件、错位、尺寸、线宽、颜色与透明边缘差异；差异明显的组件必须重做。

## 四、文字使用系统字体与可编辑文字层

1. 除强风格艺术字外，标题、职业名、按钮、标签、说明、数值等普通文字统一使用本机已安装且 Photoshop 能识别的系统字体。先检查字体实际存在及中文覆盖；不凭记忆假设字体可用。
2. 以效果图确定字重、字号、颜色、字距、行距、对齐和文本框尺寸。系统字体替换需要保持视觉层级与排版一致，不为像素完全相同而退回截图文字。
3. 普通文字在 PSD 中必须是真正的文字图层，可用文字工具直接编辑。PNG 字、栅格化文字、路径或放进智能对象的截图不能冒充文字层。
4. 强风格艺术字可单独保留图像，并在命名与清单中注明“艺术字”。不能把所有字都归为艺术字。
5. 记录使用字体的完整名称、版本（可获取时）、字号及替换情况。检查中文、标点、数字是否缺字、错字或被截断。
6. 导出工具不能写入真实 Photoshop 文字层时，切换到支持文字层的 PSD 制作方式；能力仍不足时保留素材与排版数据，明确未完成项，不交付像素字 PSD 冒充最终版。

## 五、组装完整 PSD

1. 按效果图原始尺寸建立 RGB PSD；背景、人物、UI、文字、状态分别组织并清楚命名。
2. 背景和人物取自来源清单中的对应文件夹。保留独立可见图层与透明遮罩；不将完整效果图铺在顶部。
3. 使用详细拆分后的 UI 原位组装，加入系统字体文字层。不得把 UI 总层同时开启覆盖在组件上方掩盖缺陷。
4. 当前状态默认可见，其他技能与选中状态作为清楚标注的替换层，避免多个状态同时重叠。
5. 禁止以混合背景/人物校正层、差异残留层、包含背景的截图块或隐藏的整图覆盖实现“零误差”。对照参考可以单独存放，不能参与交付合成。

## 六、复原与验收

1. 从最终 PSD 本身重新读取或导出复合图，再与原效果图做同尺寸对照、半透明叠加和差异查看；不能只验证 PNG 与自己写入的 PSD 预览一致。
2. 分别检查背景、人物、UI 和文字：素材身份、构图、比例、位置、遮挡、颜色、轮廓、边框、头像、技能和状态数量。
3. 先修正明显错位、变形、换图、边缘污染和缺件，再检查细节。系统字体替换允许字形抗锯齿等合理差异，但需检查整体排版并说明。
4. 关闭背景与人物后，UI 仍应干净；关闭某个组件后，其内容应消失，不应留有截图残影或另一层复制品。
5. 检查普通文字确为可编辑文字层，并实际检查图层名、可见状态、字体替换及缺字；未在 Photoshop 中打开时，如实说明验证环境和限制。
6. 对比指标明确比较范围，删除的背景、替换字体或遮挡补绘不能与保留像素混为“全部零差异”。不以零误差目标取代可编辑性与真实分层。
7. 尚有明显差距或缺少真实文字层时标记为草稿，继续修正或明确阻碍，不声称最终完成。

## 七、交付目录

在 `拆分ui/<界面名>/<新版本>/` 下保存：

- `UI总层.png`：通过边缘验收的第一阶段 UI。
- `组件/`：独立 PNG、各职业技能图标、头像与状态素材。
- `文字与布局.json`：字体、原文、排版参数及组件坐标。
- `<游戏名>-<界面名>-完整分层.psd`：含对应背景、人物、组件、真实文字层。
- `复原预览.png`：从最终 PSD 导出的效果图。
- `原图对比.png` 与 `验收说明.txt`：具体修正项、差异、验证环境及限制。

版本递增，保留旧文件。交付时优先提供 PSD 与对比预览链接，并简述文字层与分层验收结果。
